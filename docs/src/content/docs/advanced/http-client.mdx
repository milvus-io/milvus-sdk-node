## HttpClient vs MilvusClient

`HttpClient` uses the Milvus REST API and camelCase request fields. `MilvusClient` uses gRPC and snake_case request fields.

## When to Use HTTP Client

Use `HttpClient` in runtimes with Fetch support or on networks that require HTTP access.

## Creating HTTP Client

```ts
import { HttpClient } from '@zilliz/milvus2-sdk-node';

const client = new HttpClient({
  endpoint: process.env.MILVUS_ENDPOINT ?? 'http://localhost:19530',
  token: process.env.MILVUS_TOKEN,
});

const { code, data } = await client.listCollections({ dbName: 'default' });
if (code !== 0) throw new Error(`Milvus returned code ${code}`);
console.log(data);
```

## Using HTTP Client in Serverless Environments

See the deployment guides for [Cloudflare Workers](/milvus-sdk-node/advanced/cloudflare/), [Vercel](/milvus-sdk-node/advanced/vercel/), and [AWS Lambda](/milvus-sdk-node/advanced/aws-lambda/).

## HTTP Client Configuration

See the [constructor and per-request options](/milvus-sdk-node/api-reference/http-client/#constructor) for database defaults, timeouts, and custom Fetch implementations.

## Error Handling

Catch [`HttpError`](/milvus-sdk-node/api-reference/http-client/#errors) for non-2xx HTTP responses. Inspect the Milvus `code` in successful HTTP responses.

## Best Practices

Use environment variables for credentials and reuse the client across requests in long-running services. See [Best Practices](/milvus-sdk-node/advanced/best-practices/) for deployment advice.
