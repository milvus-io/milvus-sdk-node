---
title: 'HttpClient'
---

`HttpClient` is the REST client exported by `@zilliz/milvus2-sdk-node`. Use it when an environment prefers HTTP over gRPC, such as serverless platforms, HTTP-only runtimes, or proxy-restricted deployments.

HTTP request fields use the REST API's camelCase naming convention, for example `collectionName`, `dbName`, `outputFields`, and `indexParams`. gRPC APIs on `MilvusClient` use snake_case fields such as `collection_name` and `output_fields`.

## Constructor

```text
new HttpClient(config: HttpClientConfig)
```

```typescript
type HttpClientConfig =
  | {
      endpoint: string;
      baseURL?: string;
      database?: string;
      token?: string;
      username?: string;
      password?: string;
      timeout?: number;
      fetch?: typeof fetch;
      acceptInt64?: boolean;
    }
  | {
      baseURL: string;
      endpoint?: string;
      database?: string;
      token?: string;
      username?: string;
      password?: string;
      timeout?: number;
      fetch?: typeof fetch;
      acceptInt64?: boolean;
    };
```

`endpoint` is combined with the SDK HTTP API version. `baseURL` overrides that derived URL when provided.

Example:

```typescript
import { HttpClient, HttpError } from '@zilliz/milvus2-sdk-node';

const client = new HttpClient({
  baseURL: 'https://your-cluster.example.com/v2',
  token: process.env.MILVUS_TOKEN,
  database: 'default',
  timeout: 30_000,
  acceptInt64: true,
});
```

## Per-request options

Every HTTP method accepts an optional `FetchOptions` object.

```typescript
type FetchOptions = {
  abortController: AbortController;
  timeout: number;
};
```

Example:

```typescript
await client.search(
  {
    collectionName: 'books',
    data: [[0.1, 0.2, 0.3, 0.4]],
    outputFields: ['title'],
    limit: 10,
  },
  { abortController: new AbortController(), timeout: 10_000 }
);
```

## Collection APIs

### createCollection

`createCollection(data, options?)`

Create a collection by dimension shortcut or explicit schema.

### describeCollection

```text
describeCollection(data: HttpBaseReq, options?: FetchOptions): Promise<HttpCollectionDescribeResponse>
```

Pass `collectionName`. Optionally set `dbName`.

```ts
const { code, data } = await client.describeCollection({
  collectionName: 'books',
});
```

Returns a Milvus response envelope with collection metadata, including schema fields, indexes, and load state.

[Try the REST operation](/milvus-sdk-node/rest-api#describe-collection).

### dropCollection

`dropCollection(data, options?)`

Drop a collection.

### addCollectionField

`addCollectionField(data, options?)`

Add a field to an existing collection.

### alterCollectionProperties

`alterCollectionProperties(data, options?)`

Add or update collection properties.

### alterCollectionFieldProperties

`alterCollectionFieldProperties(data, options?)`

Alter field-level properties such as `max_length`, `max_capacity`, or `mmap_enabled`.

### dropCollectionProperties

`dropCollectionProperties(data, options?)`

Remove collection properties by key.

### listCollections

```text
listCollections(data?: HttpCollectionListReq, options?: FetchOptions): Promise<HttpCollectionListResponse>
```

All inputs are optional. Set `dbName` to choose the database.

```ts
const { code, data } = await client.listCollections({ dbName: 'default' });
```

Returns a Milvus response envelope with collection names as a string array.

[Try the REST operation](/milvus-sdk-node/rest-api#list-collections).

### hasCollection

`hasCollection(data, options?)`

Check whether a collection exists.

### renameCollection

`renameCollection(data, options?)`

Rename a collection, optionally into another database.

### getCollectionStatistics

`getCollectionStatistics(data, options?)`

Get collection statistics such as row count.

### flushCollection

`flushCollection(data, options?)`

Flush a collection.

### loadCollection

`loadCollection(data, options?)`

Load a collection into memory.

### releaseCollection

`releaseCollection(data, options?)`

Release a loaded collection.

### getCollectionLoadState

`getCollectionLoadState(data, options?)`

Get load progress and load state.

### compactCollection

`compactCollection(data, options?)`

Start collection compaction.

### getCompactionState

`getCompactionState(data, options?)`

Get compaction progress by compaction ID.

### refreshLoad

`refreshLoad(data, options?)`

Refresh an existing loaded collection.

### Collection maintenance example

```typescript
await client.flushCollection({ collectionName: 'books' });

const loadState = await client.getCollectionLoadState({
  collectionName: 'books',
});

const compaction = await client.compactCollection({
  collectionName: 'books',
});
```

## Data APIs

### insert

`insert(data, options?)`

Insert rows.

### upsert

`upsert(data, options?)`

Insert or update rows.

### get

`get(data, options?)`

Fetch rows by ID.

### query

```text
query(data: HttpVectorQueryReq, options?: FetchOptions): Promise<HttpVectorQueryResponse>
```

Pass `collectionName` and `outputFields`. Use `filter` to select rows or set a `limit` for an unfiltered query.

```ts
const { code, data } = await client.query({
  collectionName: 'books',
  outputFields: ['title'],
  limit: 5,
});
```

Returns a Milvus response envelope with matching rows.

[Try the REST operation](/milvus-sdk-node/rest-api#query).

### search

```text
search(data: HttpVectorSearchReq | HttpVectorSearchByIdsReq, options?: FetchOptions): Promise<HttpVectorSearchResponse>
```

Pass `collectionName`, `outputFields`, and either a batch of search inputs in `data` or stored primary keys in `ids`. Specify `annsField` when the collection has multiple vector fields.

```ts
const { code, data } = await client.search({
  collectionName: 'books',
  data: [[0.1, 0.2, 0.3, 0.4]],
  annsField: 'vector',
  outputFields: ['title'],
  limit: 5,
});
```

Returns a Milvus response envelope with search hits with IDs, distances, and requested fields. The aggregation overload takes `HttpVectorSearchAggregationReq` and returns `HttpVectorSearchAggregationResponse` with buckets.

[Try the REST operation](/milvus-sdk-node/rest-api#search).

### hybridSearch

`hybridSearch(data, options?)`

Hybrid search over multiple vector requests with reranking.

### delete

`delete(data, options?)`

Delete rows by filter.

### Filtering, ordering, and grouping

Use `exprParams` to bind filter placeholders such as `label in {labels}` in query, delete, search, or individual hybrid search requests. For query results, use `orderByFields` with keys such as `'price:desc'`. To group rows, pass scalar `groupByFields` and aggregation expressions such as `'count(*)'` in `outputFields`. These options were verified on Milvus 3.0.6.

REST `search()` accepts a batch of vectors or text in `data`, or searches using stored primary keys in `ids`. Pass large int64 primary keys as decimal strings. Use `orderByFields` for scalar ordering and `groupingField`, `groupSize`, and `strictGroupSize` for grouped search. Hybrid search also accepts the grouping options.

Use `functionChains` for REST search and hybrid reranking. A chain sends the protobuf stage name as a string such as `'FunctionChainStageL2Rerank'`, followed by its `ops`. In an expression argument, send a column as `{ column: '$score' }` or a JSON literal as `{ literal: 2 }`. Hybrid search accepts chains on the full request and on each sub-search. These options were verified on Milvus 3.0.6.

Pass `searchAggregation` to `search()` to return buckets for each query vector. Set `fields` and `size`, and use `metrics`, `order`, `topHits`, or `subAggregation` to customize the buckets. The response returns each query's `buckets` in `data` and the corresponding counts in `aggTopks`. Int64 bucket values and counts are decimal strings with the default `acceptInt64: false`. Milvus 3.0.6 supports this option on vector search.

## Import APIs

HTTP import APIs are separate from the gRPC `bulkInsert`, `getImportState`, and `listImportTasks` APIs.

### listImportJobs

`listImportJobs(data, options?)`

List REST import jobs for a collection.

### createImportJobs

`createImportJobs(data, options?)`

Create REST import jobs from staged files.

### getImportJobProgress

`getImportJobProgress(data, options?)`

Get progress for a REST import job.

### commitImportJob

`commitImportJob(data, options?)`

Commit an `Uncommitted` import job.

### abortImportJob

`abortImportJob(data, options?)`

Abort an import job before it commits.

### Import job example

```typescript
const job = await client.createImportJobs({
  collectionName: 'books',
  files: [['imports/books/part-0.parquet']],
});

const progress = await client.getImportJobProgress({
  jobId: job.data.jobId,
});
```

On Milvus 3.0.6, create a manual-commit job with `options: { auto_commit: 'false' }`. Poll `getImportJobProgress()` until the state is `Uncommitted`, then call `commitImportJob({ jobId })` to make the imported rows visible. To discard a staged import, call `abortImportJob({ jobId })` before committing. Poll the job again for its final state.

For Zilliz Cloud import workflows, include `projectId` and `regionId` when required by the cloud endpoint.

## Collection Schema Changes

Use `addCollectionStructField()` to add a nullable StructArray. Use `dropCollectionField()` with either `fieldName` or `fieldId`. `addFunctionField()` adds a function, its output field, and the bound index together. `dropFunctionField()` removes them together, and `alterCollectionFunction()` updates the settings supported by the server for an existing function.

`truncateCollection()` removes all rows while preserving the schema and indexes. These REST APIs were verified on Milvus 3.0.6.

## External Collection Refresh

Use `refreshExternalCollection()` to submit a refresh, `getRefreshExternalCollectionProgress()` to check its state, and `listRefreshExternalCollectionJobs()` to list jobs for a collection or database. This workflow was verified with Milvus 3.0.6.

```typescript
const {
  data: { jobId },
} = await client.refreshExternalCollection({
  collectionName: 'external_books',
});
const { data } = await client.getRefreshExternalCollectionProgress({ jobId });
```

Return the decimal job ID as-is when polling to preserve its full precision.

## Snapshot APIs

The REST snapshot lifecycle supports create, list, describe, drop, pin, and unpin. A snapshot restore returns a job ID for `getRestoreSnapshotState()` and `listRestoreSnapshotJobs()`. For portability, use `exportSnapshot()`, wait for `getExportSnapshotState()` to report completion, then pass the returned `snapshotMetadataURI` to `restoreExternalSnapshot()`.

```typescript
const {
  data: { jobId },
} = await client.exportSnapshot({
  collectionName: 'books',
  snapshotName: 'before_migration',
  targetS3Path: 'exports/books',
});
const { data } = await client.getExportSnapshotState({ jobId });
```

Snapshot job IDs, pin IDs, and int64 metadata are decimal strings so they can be passed to later requests without losing precision. Snapshot restore defaults both source and target databases to the configured database. This workflow was verified with Milvus 3.0.6.

## Resource Group APIs

`createResourceGroup()`, `describeResourceGroup()`, `listResourceGroups()`, and `dropResourceGroup()` manage resource groups over REST. Use `updateResourceGroups({ resource_groups })` to update group requests, limits, transfer preferences, and node labels. `transferReplica()` accepts `sourceRgName`, `targetRgName`, `collectionName`, and `replicaNum`.

Describe returns the server's `resource_group` object. Query node IDs in this response are decimal strings. These methods were verified on Milvus 3.0.6.

### Role privilege example

```typescript
await client.grantPrivilegeToRole({
  roleName: 'reader',
  objectType: 'Collection',
  objectName: 'books',
  privilege: 'Search',
});
```

Use `grantPrivilegeV2({ roleName, dbName, collectionName, privilege })` and `revokePrivilegeV2()` for v2 grants. The `privilege` argument accepts a single privilege or a privilege group name. Milvus requires an authenticated user for these v2 grants. Pass `dbName` to `describeRole()` to describe grants for that database. `createRole()` accepts an optional description, which `describeRole()` returns alongside grants.

Use `createPrivilegeGroup()`, `addPrivilegesToGroup()`, `removePrivilegesFromGroup()`, `listPrivilegeGroups()`, and `dropPrivilegeGroup()` to manage privilege groups. Group mutations take `privilegeGroupName`; adding or removing privileges also takes a `privileges` array. `listPrivilegeGroups()` returns each group's privilege names as a comma-separated string, matching the server response. These methods were verified on Milvus 3.0.6.

## Analyzer and File Resource APIs

Use `runAnalyzer({ text, analyzerParams })` to preview tokens for an array of strings. Pass `collectionName` and `fieldName` to use a field's analyzer. Set `withDetail` for token offsets and positions, or `withHash` for token hashes.

Use `addFileResource({ name, path })` to register a path in the server's storage, `listFileResources()` to list registrations, and `removeFileResource({ name })` to remove one. File resource IDs are returned as decimal strings. These methods were verified on Milvus 3.0.6.

## Diagnostics APIs

Use `getSegmentsInfo({ collectionID, segmentIDs })` for segment state, row counts, and binlog IDs. Pass large IDs as decimal strings. The response returns int64 IDs and row counts as decimal strings to preserve their precision.

Use `getQuotaMetrics()` to inspect quota center metrics. The response's `data` is the server's JSON text. These methods were verified on Milvus 3.0.6.

## Errors

Non-2xx responses throw `HttpError`. For HTTP success responses, inspect the Milvus response envelope. A `code` of `0` indicates success.

```typescript
try {
  await client.describeCollection({ collectionName: 'missing' });
} catch (error) {
  if (error instanceof HttpError) {
    console.error(error.status, error.statusText, error.url);
  }
}
```
