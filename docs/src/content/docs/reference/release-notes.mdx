These docs cover **SDK 3.0.11**, tested with **Milvus 3.0.6**. Check [Migration & Compatibility](/milvus-sdk-node/reference/migration-compatibility/) for server requirements.

## 3.0.11

- [`addCollectionField()`](/milvus-sdk-node/core-concepts/data-types-schemas/#structarray) accepts `parent[child]` paths to add nullable scalar, vector, and Array children to existing StructArray fields. Fixes [#672](https://github.com/milvus-io/milvus-sdk-node/issues/672).
- StructArray schema descriptions preserve the parent capacity and distinguish child nullability from parent-row nullability. Inserts preserve missing and null child positions; `PATH_REPLACE` continues to update only the supplied child.
- Nullable vector children preserve element validity on writes and reads across all five dense vector types. Whole-element `PATH_REPLACE` fills omitted nullable children with null, while child-level replacement preserves other children.
- Added serialized-request and real-server regression coverage, plus a required StructArray test matrix for contributors and coding agents.

The target server remains Milvus **3.0.6**. Adding StructArray children and using Array children require Milvus **3.0.6+**.

[Full 3.0.11 changelog](https://github.com/milvus-io/milvus-sdk-node/compare/v3.0.10...v3.0.11)

## 3.0.10

- [`count()`](/milvus-sdk-node/api-reference/data/#count) returns the original server error status with `data: 0` when a query fails, instead of throwing a `TypeError`. Check `status.error_code` before using the count. Fixes [#668](https://github.com/milvus-io/milvus-sdk-node/issues/668).
- `flushSync()` handles streaming flush checkpoints when segment IDs are not yet available, preserves database and timeout options while polling, and returns server failures.
- `HttpClient` invokes the built-in `fetch` with the global receiver required by edge runtimes.
- Updated and verified documentation examples, search metadata, Markdown mirrors, and LLM documentation bundles.

The target server remains Milvus **3.0.6**. These fixes introduce no new server version requirements.

[Full 3.0.10 changelog](https://github.com/milvus-io/milvus-sdk-node/compare/v3.0.9...v3.0.10)

## 3.0.9

- [Function chains](/milvus-sdk-node/advanced/function-chains/) extend gRPC search, hybrid search, and query. REST search and hybrid search support `functionChains`.
- [Search aggregation](/milvus-sdk-node/operations/data-operations-query/#search-aggregation) is available through gRPC and [HttpClient](/milvus-sdk-node/api-reference/http-client/#search). REST also supports search by ID, grouping, ordering, and expression parameters for query and search.
- Partial upserts can [replace individual field paths](/milvus-sdk-node/operations/data-operations-insert/) through gRPC and REST.
- Portable snapshot workflows use `exportSnapshot`, `getExportSnapshotState`, and `restoreExternalSnapshot`. Both clients support these methods.
- `MilvusClient` adds replication configuration and checkpoint APIs, duplex `createReplicateStream`, and server-streaming `dumpMessages` for WAL messages.
- `MilvusClient` adds `computePhraseMatchSlop`, `batchUpdateManifest`, and [proxy and telemetry administration](/milvus-sdk-node/api-reference/system/#proxy-administration) RPCs.
- [HttpClient](/milvus-sdk-node/api-reference/http-client/) adds collection schema changes and truncation, external refresh, snapshot jobs, manual import commit/abort, resource and privilege groups, role management, analyzers, file resources, segment metadata, and quota metrics for Milvus 3.0.6. The [REST reference](/milvus-sdk-node/rest-api/) covers all 113 server routes, including compatibility aliases and the two legacy standalone function routes.

[Full 3.0.9 changelog](https://github.com/milvus-io/milvus-sdk-node/compare/v3.0.8...v3.0.9)

## 3.0.8

- [StructArray schemas](/milvus-sdk-node/core-concepts/data-types-schemas/#structarray) support Array sub-fields. Partial upserts preserve the StructArray's type and schema.
- The SDK pins the Milvus 3.0.6 protobuf definitions. The consolidated SDK test suite runs on pull requests.

## 3.0.5

- [Bloom and Roaring filters](/milvus-sdk-node/advanced/membership-filters/): build binary membership parameters locally with `buildBloomFilter`, `BloomFilterBuilder`, `buildRoaringBitmap` and `RoaringBitmapBuilder`.
- [Client telemetry](/milvus-sdk-node/advanced/client-telemetry/): configure collection and heartbeat reporting, inspect effective settings, and handle server commands. Telemetry is enabled by default.
- [Index enums](/milvus-sdk-node/management/index-management/#additional-index-enums-in-sdk-305): `HNSW_SQ`, `HNSW_PQ`, `HNSW_PRQ`, `AISAQ`, `NGRAM` and `FMINDEX` now have `IndexType` constants. This exposes names already accepted as strings; availability depends on the server.
- Dependency updates: Parquet writer dependency updated to 1.8.9; js-yaml updated. Text embedding tests switched provider; this does not change the public SDK API.

[Full 3.0.5 changelog](https://github.com/milvus-io/milvus-sdk-node/compare/v3.0.4...v3.0.5)

## 3.0.4 additions covered here

- [Text fields](/milvus-sdk-node/core-concepts/data-types-schemas/#text): `DataType.Text`, without VarChar's `max_length` setting; requires StorageV3.
- [Function-field backfill](/milvus-sdk-node/management/collection-management/#function-field-backfill): adding a BM25 or MinHash output field starts asynchronous server backfill; monitor schema and index readiness.
- External collection field additions preserve `external_field` mappings.
