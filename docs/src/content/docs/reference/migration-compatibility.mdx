SDK **3.0.9** is tested with Milvus **3.0.6**. SDK 3.x supports core operations on compatible Milvus 2.x deployments and Zilliz Cloud. Check your server version before relying on features introduced in Milvus 3.0.

## Version Compatibility

### SDK and Milvus Compatibility

| Milvus version |            Node SDK version            | Installation                               |
| :------------: | :------------------------------------: | :----------------------------------------- |
|    v3.0.0+     | 3.0.x (3.0.9 tested with Milvus 3.0.6) | `yarn add @zilliz/milvus2-sdk-node@3`      |
|    v2.6.0+     |                 v2.6.x                 | `yarn add @zilliz/milvus2-sdk-node@2.6`    |
|    v2.5.0+     |                 v2.5.x                 | `yarn add @zilliz/milvus2-sdk-node@2.5.12` |

### Node.js Compatibility

- **Minimum**: Node.js 18+
- **Recommended**: A currently supported Node.js LTS release

## Migration Guides

### Upgrading SDK Version

1. **Check Compatibility**:
   - Verify your Milvus version supports the new SDK version
   - Review breaking changes in release notes

2. **Update Package**:

```bash
yarn add @zilliz/milvus2-sdk-node@latest
# or specific version
yarn add @zilliz/milvus2-sdk-node@2.6
```

3. **Test Thoroughly**:
   - Test all critical operations
   - Verify data integrity
   - Check performance

### Upgrading Milvus Version

1. **Backup Data**: Always backup before upgrading

2. **Check SDK Compatibility**: Ensure SDK version supports new Milvus version

3. **Update Milvus**: Follow Milvus upgrade guide

4. **Update SDK**: Update SDK to compatible version

5. **Test**: Verify all operations work correctly

## SDK 3.0.6–3.0.9 additions

- SDK 3.0.6 aligns [membership filter expressions](/milvus-sdk-node/advanced/membership-filters/) with Milvus. SDK 3.0.7 fixes core client behavior and moves CI to Milvus 3.0.6. SDK 3.0.8 adds StructArray support for nested Array sub-fields.
- SDK 3.0.9 adds path replacement in partial upserts, function chains for gRPC search and query, and REST search aggregation alongside gRPC search aggregation. Use `exportSnapshot()`, `getExportSnapshotState()`, and `restoreExternalSnapshot()` for portable snapshots.
- The public `MilvusClient` methods for replication and WAL on Milvus 3.0.6 are `updateReplicateConfiguration()`, `getReplicateConfiguration()`, `getReplicateInfo()`, `createReplicateStream()`, and `dumpMessages()`. The SDK also exposes `computePhraseMatchSlop()` and `batchUpdateManifest()`.
- The [gRPC system reference](/milvus-sdk-node/api-reference/system/) documents the proxy APIs `allocTimestamp()`, `getComponentStates()`, `registerLink()`, and `dummy()` and the telemetry APIs `getClientTelemetry()`, `pushClientCommand()`, and `deleteClientCommand()`.
- The [REST reference](/milvus-sdk-node/rest-api/) covers all Milvus 3.0.6 v2 server routes. [`HttpClient`](/milvus-sdk-node/api-reference/http-client/) exposes the canonical SDK operations for collection changes, external refresh, snapshots, imports, access control, resource groups, text analysis, and diagnostics. Use the atomic `addFunctionField()` and `dropFunctionField()` methods for function and output-field changes.

## SDK 3.0.4–3.0.5 additions

See [Release Notes](/milvus-sdk-node/reference/release-notes/) for Text fields, asynchronous function-field backfill, membership-filter builders, additional index enums and public client telemetry.

## Breaking Changes

### Version 3.0.x <span className="version-tag">Milvus 3.0</span>

- SDK 3.x targets the Milvus 3.0 proto line while keeping the public package name `@zilliz/milvus2-sdk-node`.
- Milvus 3.0-only APIs require a Milvus 3.0 server; older servers may return unimplemented or unknown-field errors.
- Legacy replicate/CDC proto fields are deprecated upstream. Avoid building new integrations on them.

### Version 2.6.x

- Enhanced type safety
- Improved error handling
- New index types support

### Version 2.5.x

- Updated connection pooling
- Improved retry mechanisms
- Enhanced logging

### Version 2.4.x

- Schema validation improvements
- Better error messages
- Performance optimizations

## Upgrade Paths

### From v2.6.x to v3.0.x <span className="version-tag">Milvus 3.0</span>

1. Upgrade Milvus to 3.0 following the Milvus server upgrade guide.
2. Update the Node SDK:

```bash
yarn add @zilliz/milvus2-sdk-node@latest
```

3. If you use new 3.0 APIs, ensure your deployment is actually connected to a Milvus 3.0 server.
4. Test collection management, write paths, and query/search result parsing before production rollout.

### From v2.3.x to v2.6.x

1. Update SDK:

```bash
yarn add @zilliz/milvus2-sdk-node@2.6
```

2. Update code (if needed):
   - Review API changes
   - Update deprecated methods
   - Test thoroughly

### From v2.4.x to v2.6.x

1. Update SDK:

```bash
yarn add @zilliz/milvus2-sdk-node@2.6
```

2. Test new features:
   - Try new index types
   - Test performance improvements

## Deprecated Features

### Deprecated Methods

Some methods may be deprecated in newer versions:

```javascript
// Old method (deprecated)
await client.alterCollection({
  collection_name: 'my_collection',
  properties: { 'collection.ttl.seconds': 7200 },
});

// New method
await client.alterCollectionProperties({
  collection_name: 'my_collection',
  properties: { 'collection.ttl.seconds': 7200 },
});
```

### Migration Steps

1. Check deprecation warnings
2. Update to new methods
3. Test functionality
4. Remove old code
